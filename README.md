# Navpaky for Windows

Navpaky (Ukrainian «навпаки», "vice versa") fixes a word typed in the wrong keyboard layout
(`ghbdtn` becomes `привет`) and switches the layout for you. It runs in the background as a tray
app. It is a Windows analog of the macOS app Rekey, written from scratch in C# / .NET 11 and WPF.

> **Status:** early development. The app starts in the notification area, keeps one instance per
> user session and stores its settings, but it does not correct text yet. The plan is in
> [docs/roadmap.md](docs/roadmap.md).

## Install

Download `NavpakySetup.exe` from the latest
[release](https://github.com/hasper16/Navpaky/releases/latest) and run it. It installs Navpaky
for your account only, without administrator rights; the first start of the wizard can take a few
seconds. The [user guide](docs/user-guide.md#installing) explains its pages.

## Prerequisites

- Windows 10 or 11
- [.NET 11 SDK](https://dotnet.microsoft.com/download/dotnet/11.0): 11.0.100 or a later 11.0
  feature band (pinned in `global.json`)

## Build, test, run

```bash
dotnet build
dotnet test
dotnet run --project src/Navpaky.App
```

`dotnet build -c Release` builds the release configuration. Warnings fail the build: the
analyzers (SonarAnalyzer.CSharp, StyleCop.Analyzers and .NET code style) run in every build.

Navpaky shows an **R** icon in the notification area; right-click it and choose **Quit** to exit.
Settings are stored in `%APPDATA%\Navpaky\settings.json`.

After cloning, turn on the repository's Git hooks (commit message format, secrets, formatting,
Core tests):

```bash
git config core.hooksPath .githooks
```

## Project layout

| Path | Contents |
|---|---|
| `src/Navpaky.Core` | Pure .NET logic: the engine (events in, actions out) and settings; no Windows APIs |
| `src/Navpaky.Win32` | Windows adapters; Win32 calls are generated by CsWin32 from `NativeMethods.txt` |
| `src/Navpaky.App` | WPF host: tray icon, start-up and shutdown |
| `tests/` | xUnit v3 tests for `Navpaky.Core` and `Navpaky.Win32` |
| `openspec/` | Specs and planned changes (spec-driven workflow) |
| `docs/` | Roadmap, architecture decisions (`docs/adr/`) and conventions |
